# rex-webview 技术原理

在 Rex 里打开网页时，原来的终端窗格还在。MyGo 创建一个独立的 macOS 窗口，用 WebKit 渲染网页；rex-webview 把这个无边框窗口放在 Rex 窗口上方，只盖住目标窗格的正文。因此 `rex capture` 读到的是下方的终端内容，不是网页图像。

## 什么时候跟随窗格

[`New`](../host.go) 用 `REX_BLOCK` 识别窗格。没有窗格 ID 时使用独立窗口，不需要安装 Rex。有窗格 ID 时优先使用 `REX_SESSION`；从 Rex preview.23 起，新窗格不再设置这个变量，`New` 会调用一次 `rex whoami --json` 读取 `session_id`。`session.view` 需要会话 ID，不能拿窗格 ID 代替。查询失败时 `New` 返回错误，不会启动 Rex 服务器或改用独立窗口。

[`Run`](../pane_darwin.go) 从 `main` 启动 MyGo 的事件循环，一个进程只能运行一个宿主一次。窗口起初隐藏：在普通终端里，宿主装好回调后直接显示窗口；在 Rex 里，由跟随器决定何时显示。`Offscreen` 让窗口一直隐藏，在 Rex 里仍会跟踪布局，但不安装用于摆放窗口和接收快捷键的原生覆盖层。

## 从布局事件到屏幕坐标

分屏和拖动窗口是两种不同的变化。分屏会改变窗格在布局里的比例，所以 [Go 跟随器](../follow.go) 通过 [`rex` 命令行](../rexcli.go) 调用 `session.view`，缓存目标窗格的比例矩形。`rex events` 通知它重新取布局；连接和断开事件除外，否则取布局的命令本身又会触发刷新。即使漏掉了事件，跟随器也会每 5 秒重取一次布局。

拖动整个 Rex 窗口时，窗格比例不变，变的是屏幕坐标。原生窗口代码（开 cgo 时是 [pane_darwin.m](../pane_darwin.m)，`CGO_ENABLED=0` 时是 [native_purego_darwin.go](../native_purego_darwin.go)）在 AppKit 主线程上用定时器读取 Rex 窗口的边界，结合缓存的布局来摆放网页窗口。前台定时器的间隔约为 1/60 秒，不需要每帧都调用 `rex`。

两份原生实现做的事一样：查 Rex 窗口位置和遮挡关系，摆放网页窗口，监听按键，在 Rex 回到前台时调整层级和焦点。不开 cgo 时，purego 直接给 AppKit 发 Objective-C 消息，并调用 CoreGraphics 和 CoreFoundation 的函数，MyGo 自己的 macOS 后端也是这么做的。两份实现都只把窗口位置、按键和激活事件交给共用的 Go 代码，由 Go 代码决定显示位置和焦点归属。两种构建的性能对比见[测试报告](test-report.md)。

以[几何测试](../geometry_test.go)里的右下窗格为例。下表的矩形都按 `[左, 上, 宽, 高]` 排列，屏幕距离的单位是点，不是像素。

| 换算步骤 | 矩形 | 含义 |
| --- | --- | --- |
| 取 Rex 窗口边界 | `[100, 50, 1048, 616]` | 来自 macOS 窗口列表 |
| 扣除 Rex 界面 | `[108, 58, 800, 600]` | 右侧栏占 240 点，其余三边各留 8 点 |
| 应用窗格比例 | `[508, 358, 400, 300]` | 布局给出的 `[0.5, 0.5, 0.5, 0.5]` 表示右下四分之一 |
| 换算正文边缘 | `[513, 398, 394, 259]` | 这两级都是对半分屏，左、上各让 4 点，再保留 36 点标题栏及左、右、下各 1 点描边 |

分隔条占的是父窗格的空间，不是每个叶节点固定扣半个间隙。例如 800 点宽的父窗格按 1:3 分屏，间隙为 8 点，右窗格从 `(800 - 8) / 4 + 8 = 206` 点处开始，不是 `800 / 4 + 4 = 204`。嵌套分屏逐级累计这个修正；浮层外沿没有分隔条。

[几何计算](../geometry.go)到这一步得到的是以主屏幕左上角为原点的正文矩形。AppKit 的原点在左下角，所以设置网页窗口位置时，纵坐标要换成 `主屏幕高度 - (上 + 高)`。

Rex 或网页窗口在前台时，网页窗口在浮动层级上。否则网页窗口有焦点时点 Rex 的别的窗格，Rex 一激活就把自己的窗口提到前面盖住网页，网页会闪一下。切到别的应用时，网页窗口回到普通层级，贴在 Rex 窗口上面，别的应用的窗口可以盖住它。

Rex 没有直接提供正文的屏幕矩形。跟随器每秒读取 Rex 的侧栏、工具栏、窗格密度和外观等设置，再用按 Rex 0.1.0 preview 界面测得的尺寸换算。Rex 改版可能使网页边缘错位。打开多个 Rex 桌面窗口时，原生层按窗口列表挑选最靠前且符合条件的 Rex 窗口，并不按会话 ID 精确匹配。这套定位只适用于本机的 Rex 桌面窗口。

横排标签的 `tabBarEdge=bottom` 会把工具栏所占空间移到下沿，平铺和浮层画布都从普通上边距开始；顶部标签和竖排侧栏保持各自的计算。这个修正参考 [Leaf PR #87](https://github.com/DeepanshuMishraa/leaf/pull/87)。紧凑模式同步 Leaf 对 preview.23 的测量，使用 34 点标题栏、1 点分隔条；浮窗仍保留 10 点圆角。

`ExperimentalFloatingPanes` 开启时，跟随器也查找未最小化的浮层。Rex preview.21 在 `session.view` 中按从后到前列出各层：`bounds` 是整层占据的范围，叶节点的 `rect` 是各窗格在窗口布局中的位置。即便浮层里还有分屏，也不能再用 `bounds` 乘一次 `rect`，否则偏移和尺寸都会出错。是否遮挡看层的顺序，而不是猜哪个窗格有焦点。拖动期间和浮层边缘的点数尚未在独立 Rex 桌面窗口中校准。

竖排标签下，浮层画布比平铺区低 34 点，因此不能直接对比例矩形做相交判断。跟随器保存上层的 `bounds`，每帧按浮层画布换算成屏幕矩形，再和网页正文相交；上层范围未知时暂时隐藏。移动或缩放同一 `layer_id` 时，只要叶节点在层内的相对位置、尺寸和接缝未改变，就不重新等待布局动画。

标题栏拖动沿用 Leaf 的 `FloatDrag` 路径，由全局鼠标监听接收按下、拖动和松手事件。共享的 [float_drag.go](../float_drag.go) 保存按下时的正文矩形和鼠标位置；原生层在按下时检查实际命中的最上层普通／浮动窗口，只接受目标 Rex 窗口，避免 Command 拖动其他后台窗口因坐标重合而误触发。按下后立即保留拖动状态，长按尚未移动时也不会被焦点恢复打断。原生层按鼠标位移直接调用 `setFrameOrigin:`，只移动窗口，不调用带重绘的 `setFrame:display:`。拖动期间定时跟随跳过窗口查询和旧布局定位，避免被拉回原处。松手事件也先移到最终位置，再安排一次后台布局刷新；只接受松手之后开始的查询，以及相对于松手时已有布局的新位置作为落点确认。收到确认或等待 500 毫秒后恢复普通跟随。

拖动只从浮窗标题栏中间开始，上沿和左右各留 7 点给 Rex 的缩放边缘；没有标题栏时不启用。切换会话、窗格隐藏、移动到其他浮层、新的鼠标按下或宿主退出会取消预览。cgo 和 purego 共用拖动状态和计算，原生层分别处理鼠标事件和 AppKit 坐标换算。窗格和浮层的创建、移动规则及缩放仍由 Rex 管理。

## 隐藏不等于关闭

切到其他标签、放大别的窗格，或有浮层与目标平铺窗格相交时，网页窗口会让开，页面仍然保留。放大目标窗格时则按整个布局区计算。窗格比例或可定位状态发生变化后，跟随器会等约 100 毫秒再显示，避开 Rex 的布局动画。

切到同一会话的其他标签时，布局事件会触发刷新。切到另一个会话的标签时，Rex 服务器不发事件，只有 Rex App 设置里的 `Workspace.lastFocusedSession` 会变。跟随器在单独的循环里每 30 毫秒读一次这项设置，读一次只要几微秒，不会和取布局的 `rex` 命令互相耽误。

`Host.Where()` 的 `placed` 只说明最近一次布局能否给出窗格位置，不代表网页正在屏幕上显示。比如 Rex 的命令面板挡住正文时，布局仍能给出位置，但原生层会根据窗口遮挡关系隐藏网页。

要判断窗格是否关闭，跟随器会在整个会话的所有标签和层中查找目标。只有连续两份成功取得的布局都找不到它，才触发一次 `OnPaneGone` 处理，默认退出。查询失败只会让窗口暂时失去位置，不算作窗格消失。

## 键盘焦点如何交接

点击网页时，如果 Rex 的焦点还在别的窗格，宿主会调用 `session.focus_block` 把两边对齐。反过来，Rex 把焦点移到别的窗格时，如果网页窗口正在接收键盘输入，宿主会把键盘还给 Rex。

Rex 回到前台约 0.25 秒后，宿主会发起新的布局查询，再按新布局决定是否把键盘接回网页窗口。命令面板或对话框关闭后也这样处理；遮挡检查覆盖 Rex 的普通和浮动窗口层级，并在网页重新显示前执行。查询失败、焦点已换到别的窗格、会话已切换时都不接回焦点。请求之前已经开始的查询不能授权恢复；布局仍在等待动画时，等网页实际显示再接回。

恢复请求之前 0.75 秒内如果点过鼠标，并且点击位置在新窗格外（包含标题栏），宿主就不接回键盘。宿主保留请求时间，查询慢也不会忘记这次点击。点击由原生层的全局鼠标监听记录，这种监听不需要辅助功能权限。比如点侧栏里另一个会话的 tab 时，这个会话里的焦点不会变；以前宿主会把键盘抢回来，这一下点击就失效了，tab 切不过去。刚转发给 Rex 的快捷键仍保留 1 秒的焦点保护；保护期间保留待恢复请求，结束后重新检查焦点和可见性。

网页有焦点时，原生层只监听自己窗口的按键。跟随器用 `rex keymap --json` 里的绑定和一组内置的 Rex 快捷键匹配：比如按 `⌘D` 命中默认分屏动作后，宿主通过 `client.perform` 请 Rex 分屏，而不是把按键打进终端。带 `mode` 的绑定不转发，因为宿主不知道 Rex 当前在哪个按键模式。普通文字留给网页，`⌘W`、`⌘Q` 和 `ReservedKeys` 不转发给 Rex。

关闭网页窗口或请求退出时，宿主默认取消运行上下文。设置 `OnClose` 后，回调可以先保存数据，再取消上下文；不取消，页面就留着。直接取消上下文不会触发 `OnClose`。退出时宿主移除原生监听器和定时器，并等待后台的 Rex 命令结束。
